BlunderNet ↗

live at blundernet.com, 120+ players

I made LeetCode for chess. 3.25 million puzzles you can filter by rating, theme, phase and length, plus a bot ladder to play against. There is also a classroom mode, where a coach's board goes out live over a socket and the answers come back grouped by move with a count. A review judges every move by the winning chances it cost rather than by centipawns, brilliant down to blunder, on a game played there or pasted in from any site. Every position is written out for a screen reader too, and a blindfold toggle hides the pieces without taking them off the board. Drawing a random puzzle from six million rows took 1.4 seconds with ORDER BY random(); a precomputed grid and a stored shuffle key took it to 0.9 ms. The Go API holds no state, so live games sit in Redis and any instance can serve any game, and engine inference runs on SQS-fed ONNX workers that autoscale under backlog. When search got slow I traced it to cold disk reads at 92% utilisation and cut pages touched from 55,821 to 20,602. The whole AWS stack is Terraform, and the site publishes its own latency targets and whether it is currently meeting them.

Go · AWS · Terraform · Postgres · Redis · ONNX · k6

BlunderNet Engine ↗

the network and the search

AlphaZero-style engine: residual CNN with policy and value heads, PUCT Monte-Carlo tree search written in C++ and bridged to Python with pybind11 for a 1.8× speedup. A scheduled GitHub Actions pipeline runs the whole cycle without me, pulling fresh games from the top Lichess blitz players, retraining, and evaluating. Self-play feeds back in too, though the supervised stream is what does most of the work so far. Strength gets checked against held-out move prediction, a 1,200-puzzle tactics suite, and matches versus Stockfish.

PyTorch · C++ · pybind11 · GitHub Actions

Vestigo ↗

live at vestigo.earth, where was this photo taken and how do you know

An agent that works out where a photograph was taken, at the most specific level the evidence supports. Most systems return a point no matter how little they have to go on, so the metric here is calibration rather than distance. I measured a plain model call first, before building anything, so every later number has something to sit against: 2.6 km median on landmarks, 94 km on rural roads. Then seven evaluation runs, three samples per photograph, because run-to-run noise turned out to be a 40 km median with a 14,951 km tail and a single sample cannot tell an improvement from a reroll. The change that mattered was taking the grading of evidence away from the model: it could put 0.9 on “dry scrub” and push a street-level claim through, so evidence now carries the finest level it can justify and the most any citation of it is worth. Overclaiming fell from 29% to 16% with accuracy unmoved, which is the same answers stated at levels they can carry. I also trained the classifier that feeds it: 20,000 images, frozen CLIP, 236 geocells clustered on the sphere rather than gridded, and temperature scaling that takes calibration error from 10.7% to 1.4%, making it the only evidence source whose confidence is measured rather than asserted.

Python · LLM agents · tool calling · PyTorch · CLIP · eval harness · pytest
